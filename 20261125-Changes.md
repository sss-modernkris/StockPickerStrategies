## 1. Objective

Allow users to **manually type any ticker symbol** (e.g., `PLTR`, `AMD`, `NFLX`) in the **Execution Playground** of the **Brokers** tab in addition to selecting from the existing preset dropdown (**Stage 1 Recommendations**, **Current Holdings**, and **Standard Equities**).

---

## 2. Implementation Plan

1. **Dual Ticker Input + Quick-Select Dropdown (`frontend/src/components/BrokersPanel.tsx`)**:
   - Add a manual text `<Input>` field (`placeholder="Type ticker (e.g. PLTR, AMD)"`) bound directly to `tradeTicker` with automatic uppercasing and whitespace stripping.
   - Trigger live quote retrieval (`fetchTickerPrice`) automatically on `Enter`, `onBlur`, or via a dedicated **Quote** button adjacent to the input — avoiding redundant API calls on every keystroke.
   - Keep the existing `<select>` dropdown directly below with **Stage 1 Recommendations**, **Current Holdings**, and **Standard Equities**, plus a `"— Or select from quick list —"` fallback option when a custom symbol is typed.
2. **Order Validation & Fractional Quantity Support (`frontend/src/components/BrokersPanel.tsx`)**:
   - Normalize (`tradeTicker.trim().toUpperCase()`) and validate non-empty ticker symbols in both `handleRhTradeSubmit` (**Execute Order**) and `handleRhTradePreview` (**Preview Order**), encoding the ticker safely with `encodeURIComponent`.
   - Add `step="any"` to the **Quantity** `<Input>` so manual fractional-share orders (e.g., `0.5`) can be entered without HTML5 browser step validation errors.
3. **Verification**:
   - Confirm Next.js Fast Refresh / compilation on `http://localhost:3000` (`HTTP 200`).
   - Verify live quote retrieval for a custom ticker not in the preset dropdown (`/api/quote/PLTR`).

## 5. On-Demand Account Balances & Active Holdings Refresh Button

### Objective
Add an on-demand refresh button in the **Brokers** tab so clicking it immediately reads current account balances (**Cash Available**, **Invested Capital**, **Total Net Equity**) and **Active Stock Holdings** directly from the connected Robinhood MCP (or Sandbox) account.

### Implementation Plan
1. **Fresh Account Fetch Handler & State (`frontend/src/components/BrokersPanel.tsx`)**:
   - Add `accountRefreshing` (`boolean`) and `lastAccountSync` (`string | null`) state variables.
   - Update `fetchRhData()` to call `${API_BASE_URL}/api/rh/data?_t=${Date.now()}` with `cache: 'no-store'` to guarantee fresh reads without browser caching, and record `lastAccountSync`.
   - Add `handleRefreshAccountData()` to refresh `/api/rh/data` and `/api/rh/config` in parallel, with loading state and user-facing success/error feedback.
2. **UI Placement (`frontend/src/components/BrokersPanel.tsx`)**:
   - Add an **Account Balances & Active Holdings** header bar directly above the 3 balance cards displaying `Last synced: HH:MM:SS` and a prominent **Refresh Balances & Holdings** button (with spinning `RefreshCcw` icon).
   - Add a quick **Refresh** button in the **Active Stock Holdings** card header next to the `X Held` badge.
