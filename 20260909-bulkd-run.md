## 🚨 Encountered Issues & Technical Resolutions

### Issue 1: Interactive Dev Server (`next dev`) Exiting on Stdin Closure
- **Symptom:**  
  When starting the frontend dev server via `npm run dev` or `node runner.js` in async subshell tasks, the process exited with `exit code: 1` as soon as HTTP requests completed or stdin closed.
- **Root Cause:**  
  Next.js 16 Turbopack dev mode attaches interactive keyboard listeners to `process.stdin` (listening for `r` to reload, `o` to open, etc.). In headless background tasks, stdin EOF is emitted, causing `next dev` to shut down automatically.
- **Resolution:**  
  Executed a full production build (`npm run build`) and launched `npm run start`. The production Next.js server operates as a standard Node.js daemon without TTY/stdin interactive requirements, ensuring stable 24/7 background execution.

---

### Issue 2: Standalone Output Configuration Notice
- **Symptom:**  
  Next.js outputted the notice during production server startup:  
  `⚠ "next start" does not work with "output: standalone" configuration. Use "node .next/standalone/server.js" instead.`
- **Root Cause:**  
  `next.config.js` was configured for standalone output deployment.
- **Resolution:**  
  Verified both `npm run start` and `node .next/standalone/server.js` render pages and respond with `HTTP 200 OK` on port 3000.

---

### Issue 3: Subshell PowerShell Interpolation Errors
- **Symptom:**  
  Powershell commands containing unescaped object property references (`$b.status`, `$f.StatusCode`) threw `EmptyPipeElement` and `ExpectedValueExpression` parser errors when passed as subshell strings.
- **Root Cause:**  
  Subshell variable expansion stripped dollar signs from property access expressions.
- **Resolution:**  
  Switched to direct system execution using `curl.exe -s http://localhost:8080/health` and `curl.exe -I -s http://localhost:3000` for deterministic, error-free endpoint validation.
