## 3. Implementation Plan — Dynamic `Available Cash ÷ N Tickers` Strategy

### Objective
Update the **Brokers** tab fractional share sizing strategy so available deployable cash is divided by the **actual number of qualified stock tickers to buy ($N = \text{num\_candidates}$)** instead of a hardcoded divisor of `5`.

### Planned Changes
1. **Dynamic Per-Ticker Capital Division (`backend/agents/broker_agent.py`)**:
   - When `num_candidates > 0`:
     - `required_for_full_2k = 2000.0 * num_candidates`
     - If `deployable_capital >= required_for_full_2k`, set `per_stock_budget = 2000.0`.
     - Otherwise, set `per_stock_budget = math.floor((deployable_capital / num_candidates) * 100.0) / 100.0`.
   - When `num_candidates == 0`, set `per_stock_budget = 0.0` (avoiding division by zero).
   - Raise `effective_cap_pct` to `min(100.0, (100.0 / num_candidates) + 1.0)` when sizing equal-weight allocations so portfolios with fewer than 4 qualified tickers (e.g., 2 tickers at 50% each or 3 tickers at 33.3% each) are not throttled by the default 25% single-position cap.
2. **Live Gateway & Approval Plan Cap Alignment (`backend/trading/live_gateway.py`, `backend/trading/approval.py`)**:
   - Add `supports_position_cap_override = True` and optional `position_cap_override_pct: Optional[float] = None` to `LiveExecutionGateway.place_stock_order()`.
   - Pass the computed equal-weight cap override (`min(100.0, (100.0 / N) + 1.0)`) from both `BrokerAgent` and `ApprovalManager.execute_approved_plan()` while preserving the default 25% single-position cap on standalone manual orders.
   - Add `+ 0.05` rounding tolerance on buying power, daily spend, and position cap checks for fractional-share cent rounding.
3. **Frontend UI & Strategy Glossary Updates (`frontend/src/components/BrokersPanel.tsx`, `frontend/src/components/StrategyGlossary.tsx`)**:
   - Update all `Avail÷5` / `÷ 5` badges, buttons, tooltips, toast messages, and glossary formulas to **`Avail÷N`** / **`÷ N`** (number of qualified tickers to buy).
